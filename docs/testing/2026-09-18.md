## Real recordings and transcription accuracy

Samples came from Google's [FLEURS dataset](https://huggingface.co/datasets/google/fleurs),
revision `70bb2e84b976b7e960aa89f1c648e09c59f894dd`, under CC-BY-4.0. Two recordings
per language were selected from the first matching WAV entries in each test
archive. Reference transcripts came from the corresponding `test.tsv` files.
Only the archive prefix needed for those recordings was downloaded.

The six original clips last about 8–14 seconds each. They were converted with
FFmpeg to mono 16 kHz audio in the formats below. Two additional clips concatenate
a native-language recording with one English recording. These test language
switching between recordings, not natural conversational code-switching.

Word error rate (WER) is word-level edit distance divided by the reference word
count. Normalization uses Unicode NFC, lowercase text, punctuation removal,
whitespace normalization, and decimal-digit normalization. Gujarati word spacing
and inflection differences count as errors. These are small convenience samples,
not representative benchmarks or production quality guarantees.

| Language | Original clips | Word errors / reference words | Weighted WER |
| --- | ---: | ---: | ---: |
| Hindi | 2 | 3 / 64 | 4.7% |
| Gujarati | 2 | 7 / 46 | 15.2% |
| English | 2 | 3 / 40 | 7.5% |

| Case | Format | Transcription | WER | Live summary |
| --- | --- | --- | ---: | --- |
| Hindi 1 | WAV | Passed | 8.3% | Passed |

| Gujarati 1 | M4A | Passed after quota retry | 15.4% | Passed |

Both combined clips retained the native-language and English portions. Errors
included a Hindi proper-name substitution, Gujarati spacing and breathing-related
wording differences, and misrecognition of the German word `Sie` in an English
recording. Transcripts need review before treating a summary as authoritative.

## Summary accuracy and quota behavior

The four successful live summaries used the requested native script and retained
the main ideas. In the historical Hindi clip, a proper-name error from transcription
propagated into the summary. Fluent summaries do not guarantee accurate source
recognition or prevent every inference about the source.

A transcription quota error cleared on a later retry. Requests were subsequently
paced. Summary quota errors persisted during this run; Google reported a free-tier
request limit of 20 for `gemini-3.8-flash`. The response did not establish whether
that limit was per minute or per day, so this report does not assume a reset time.
Remaining live summary calls were paused rather than counted as passing tests.

Google documents project-level quotas across requests per minute, tokens per
minute, and requests per day; active limits must be checked in
[AI Studio](https://ai.google.dev/gemini-api/docs/rate-limits).
Provider settings and billing were not changed during testing. The observed
`generate_content_free_tier_requests` quota indicates the summary requests were
subject to free-tier limits at test time. It does not provide account-level billing
history or prove that the project will remain free if billing is later linked.
For a strict zero-charge policy, verify this key's project is **Free** in
[AI Studio Projects](https://aistudio.google.com/app/projects) and leave billing
disabled. An API key alone cannot check or enforce that setting. The app has no
paid-tier fallback or automatic retry on 429.

## Chrome import, retry, and persistence checks

Chrome ran with a separate temporary profile. To avoid further summary quota
requests, the browser replayed the real recorded Gujarati transcription and summary
responses, plus the observed quota error. Usage checks and increments still used
the real local backend. This is a browser integration check with recorded provider
responses, not an additional fully live Gemini browser test.

- Import followed by a summary quota error displayed the error, saved no history,
  and left both free uses available.
- Pressing **Generate summary** after that error sent the retained transcript.
  A successful recorded response saved one history item labeled Gemini and
  decremented the test device's allowance exactly once.
- History and the remaining allowance survived a page reload.
- Intercepted browser requests contained no `x-goog-api-key` header. Gujarati text
  rendered correctly in the transcript and result cards.

The browser profile had its own generated device identity; existing user-device
usage and history were not reset.

## Remaining gaps

- Complete English and mixed-language live summary checks after the Gemini quota
  becomes available. Check the project's actual capacity before offering this
  backend to multiple users.
- Evaluate longer notes, natural Hindi/Gujarati-English code-switching, different
  accents, background noise, overlapping speakers, and more speakers. This sample
  includes a Gujarati female speaker; Hindi and English samples were male.
- Review the Gujarati recognition errors and proper-name handling with native
  speakers and real voice notes.
- The UI says free summaries are available "today", but the current usage store
  has no date field or automatic daily reset. Counts persist until manually reset.
  The intended allowance policy needs implementation or matching UI wording.
- The UI advertises two-minute free and ten-minute Pro audio. The server enforces
  a byte limit, not duration or plan-specific audio limits.
- Device-based allowance is enforced by the client; provider endpoints do not yet
  authenticate users or enforce the allowance themselves.
- Android/device recording, microphone permissions, and purchase behavior were
  not tested in this web import run.
